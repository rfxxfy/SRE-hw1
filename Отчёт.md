# Отчёт по заданию 1

## Доменная область

Приложение «Список задач» позволяет вести личные дела: создавать задачи, просматривать их, менять название, описание и отметку о выполнении, удалять задачи. Интерфейс обращается к серверу по HTTP/1.1 через JSON REST API. Сервер хранит данные в PostgreSQL.

## Стек

- Бэкенд: Python 3.12, Flask, Gunicorn, драйвер psycopg.
- Фронтенд: HTML, CSS, JavaScript без сборки и сторонних библиотек.
- СУБД: PostgreSQL 16.
- Запуск: Docker и Docker Compose.

## Основные сущности

**Задача (`tasks`)**: числовой `id`, обязательное `title`, необязательное `description`, признак `done`, время создания `created_at` и изменения `updated_at`. Все CRUD операции доступны через `/api/tasks`. Схема создаётся отдельной командой `python -m app.migrate`.

## Соответствие 12 факторам

| № | Фактор | Реализация |
| --- | --- | --- |
| 1 | Кодовая база | Одна кодовая база в Git. Из неё собирается образ для веб-процесса и административной команды миграции. |
| 2 | Зависимости | Python-пакеты явно перечислены с версиями в `requirements.txt`, устанавливаются в образе. Для работы не требуются пакеты из глобального Python хоста. |
| 3 | Конфигурация | Адрес БД `DATABASE_URL`, пароль `PGPASSWORD`, порт `PORT` и число процессов `WEB_CONCURRENCY` задаются переменными окружения. `.env` не коммитится; `.env.example` содержит только пример. |
| 4 | Сторонние службы | PostgreSQL подключается по URL из окружения. Базу можно заменить другой PostgreSQL без изменения кода. |
| 5 | Сборка, релиз, запуск | `Dockerfile` собирает образ; сервис `migrate` выполняет подготовку схемы; `web` запускает тот же образ после успешной миграции. Код в работающем контейнере не меняется. |
| 6 | Процессы | Веб-процессы не хранят состояние между запросами. Данные живут в PostgreSQL; файлы контейнера не используются для хранения задач. |
| 7 | Привязка к порту | Gunicorn слушает HTTP на `0.0.0.0:$PORT` (по умолчанию 8000), Compose публикует этот порт. |
| 8 | Параллелизм | Несколько независимых Gunicorn workers (`WEB_CONCURRENCY`, по умолчанию 2) обрабатывают запросы; каждый обращается к общей БД. Допустимо запустить несколько экземпляров `web`. |
| 9 | Одноразовость | Веб-процессы быстро стартуют, не содержат локального состояния, Gunicorn корректно завершает workers по сигналу, операции с БД выполняются в транзакциях. |
| 10 | Сходство сред | Для разработки и запуска используется одна конфигурация Compose, тот же образ приложения и PostgreSQL 16. Переменные окружения позволяют менять настройки сред без правки кода. |
| 11 | Журналы | Gunicorn пишет журналы доступа и ошибок в stdout/stderr; Compose собирает их, например `docker-compose logs web`. Файлы логов приложение не ведёт. |
| 12 | Административные задачи | `python -m app.migrate` запускается как отдельный разовый процесс из того же образа и с тем же подключением к БД. |

## Как проверить

После `docker-compose up --build -d` откройте <http://localhost:8000>. Создайте задачу, измените её название и отметку выполнения, затем удалите. Те же операции доступны через REST API, описанный в `README.md`. После перезапуска контейнеров неудалённые задачи остаются в томе PostgreSQL.
